# Устранение неполадок (TROUBLESHOOTING)

## Быстрая самодиагностика
Откройте **Настройки → Сетевой доктор** (или Центр защиты) и нажмите **Запустить проверки**:
- проверяется целостность бинарников (`xray.exe`, `wireproxy-awg.exe`, `wintun.dll`) по SHA-256;
- проверяется наличие прав администратора, конфликтующие виртуальные VPN-адаптеры и диапазоны `netsh excludedportrange`;
- тестируются локальные порты, системный прокси, DNS (включая DoH/DoT) и сквозной проход через туннель.

## Частые ситуации
| Симптом | Причина и решение |
| --- | --- |
| **Ошибка прав для Kill Switch / TUN** | Запустите AURA VPN от имени администратора или переключитесь на режим **Системный прокси**. При остаточных правилах после сбоя нажмите **Снять с правами UAC** или откройте **Центр защиты → Экстренное восстановление сети**. |
| **Нет интернета после аварийного закрытия с Kill Switch** | Откройте **Настройки → Безопасность** или **Центр защиты** и нажмите **Экстренное восстановление сети** — будут сняты фильтры WFP/`netsh` и восстановлены системные параметры прокси. |
| **Подписка вернула ошибку редиректа / SSRF** | Убедитесь, что URL подписки ведёт на публичный HTTPS/HTTP адрес (локальные `127.0.0.1`, `10.x`, `192.168.x` и loopback-адреса отклоняются политикой безопасности `net_fetch`). |
| **После обновления подписки пропали или сломались узлы** | Нажмите **Откатить узлы** на баннере изменений во вкладке **Подписки** — клиент восстановит список серверов из зашифрованного снимка перед обновлением. |
| **Прокси остался включён в системе после сбоя** | При нормальном выходе и переподключении прокси сбрасывается автоматически. Также можно нажать **Экстренное восстановление сети** в Центре защиты или **Сбросить системный прокси** в диагностике. |
| **Узел не работает с системным прокси или требует другой DNS/MTU** | Нажмите иконку **Инспектора узла** в списке серверов (или на главной) и проверьте отчёт Smart Config Engine: при необходимости задайте индивидуальный режим **TUN**, **MTU** или персональный **DNS**. |
| **WireGuard / AmneziaWG не подключается** | Проверьте корректность Base64-ключей и параметров `Jc`/`Jmin`/`Jmax`/`S1`/`S2` в Инспекторе узла или предпросмотре импорта (`vpn://` / `.conf`). |
| **Повреждённый файл настроек** | При повреждении JSON-хранилище переносится в резервный файл `.corrupt`, а клиент продолжает работу с безопасными значениями по умолчанию. |
