# Архитектура безопасности AURA VPN (`v0.8.0`)

Документ описывает модель угроз, границы доверия и механизмы защиты клиентского приложения **AURA VPN** для Windows.

## 1. Локальное хранение и шифрование (Windows DPAPI)
- Все чувствительные хранилища в `%APPDATA%\app.auravpn.desktop\` (`profiles.json`, `subscriptions.json`, `history.json`, `ip-monitor.json`, `sub-backups/*.json`, `profile-history/*.json`) шифруются на уровне текущего пользователя Windows через `CryptProtectData` / `CryptUnprotectData` (`src-tauri/src/storage.rs`).
- Миграция устаревших открытых файлов (`v0.4.0`–`v0.7.0`) выполняется автоматически с записью зашифрованной версии. Повреждённые файлы изолируются в карантин (`.corrupt`).
- Временные файлы конфигурации сессии (`xray.json`, `awg.conf`) при отключении, смене сервера или сбое перезаписываются нулями, синхронизируются (`sync_all()`) и удаляются (`secure_delete_file`).
- При старте запускается очистка осиротевших временных файлов (`sweep_stale_runtime_files`) в рабочем каталоге, `runtime/` и `rulepacks/*.tmp`.

## 2. Проверка целостности встроенных бинарников
- Эталонные SHA-256 хеши для `xray.exe`, `wireproxy-awg.exe` и `wintun.dll` фиксируются в сборке (`src-tauri/build.rs`). В release-сборке пустой или некорректный манифест прерывает компиляцию на этапе сборки.
- Перед каждым запуском туннеля `core_manager.rs` сверяет фактический SHA-256 исполняемых файлов с вшитым эталоном. В привилегированном (UAC) режиме проверка не полагается на кеш времени модификации файла.

## 3. Защита сетевого загрузчика (`net_fetch.rs`)
- Подписки, обновления rulepack и лента обновлений поддерживают строгий SSRF/DNS-rebinding контроль:
  - домен резолвится предварительно, и каждый IP проверяется на каждом шаге редиректа (с ограничением числа редиректов);
  - запрещены loopback, link-local, RFC1918/ULA, CGNAT, multicast, IPv6 NAT64 (`64:ff9b::/96`), 6to4 (`2002::/16`), Teredo (`2001::/32`), документационные сети (`2001:db8::/32`) и IPv4-mapped/compatible IPv6 адреса;
  - установлен суммарный таймаут загрузки (`30 с`) и ограничение максимального объёма тела ответа.

## 4. Защита парсеров, Smart Config Engine и Xray-конфигов
- Парсер подписок Clash/YAML переведён с депрецированного `serde_yaml` на чистый Rust-парсер `yaml-rust2` (`src-tauri/src/parser/clash.rs`): алиасы и якоря (`&` / `*`, Billion Laughs), а также глубина вложенности > 32 жёстко отклоняются.
- **Smart Config Engine** (`src-tauri/src/config_analyzer.rs`) анализирует возможности узлов до применения и гарантирует, что пер-серверные `ProfileOverrides` (MTU в диапазоне 1280–1500, персональный DNS, предпочтительный режим) не могут ослабить глобальную политику Kill Switch и системные маршруты; при `dns_mode != direct` адрес удалённого сервера разрешается заранее для исключения DNS bootstrap deadlock.
- Генераторы конфигураций WireGuard/AmneziaWG (`wireproxy_ini.rs`) и Xray (`xray_config.rs`) валидируют ключи, адреса, хосты и параметры транспорта от инъекций управляющих символов, переводов строк и секций `[Section]`.
- Внешние ссылки обновлений (`updater.rs`) ограничены HTTPS-адресами GitHub Releases или тем же origin, что и заданная пользователем лента обновлений.

## 5. Kill Switch 2.0, WFP и Proxy Guard (`kill_switch.rs`)
- **4 режима работы**: `off` (выключен), `on_drop` (блокировка при обрыве или переподключении, снятие при штатном отключении), `always_on` (постоянная защита при запущенном клиенте), `routing_aware` (учитывает разрешённый прямой трафик для исключений маршрутизации).
- **WFP (Windows Filtering Platform)**: при наличии прав администратора используется нативная динамическая сессия (`FWPM_SESSION_FLAG_DYNAMIC`) для системного уровня защиты в TUN-режиме; при аварийном завершении процесса ядро Windows автоматически удаляет динамические фильтры, если не включён opt-in `persistOnExit`.
- **Проверенный fallback на `netsh.exe` и Proxy Guard**: путь к `netsh.exe` разрешается строго через `GetSystemDirectoryW`; в режиме системного прокси активна заглушка/перенаправление без обхода (`Proxy Guard`), а также исключения LAN/DHCP и блокировка IPv6 при включённой защите утечек.
- **Экстренное восстановление сети** (`emergency_recover_network`): единая безопасная процедура снятия фильтров WFP, правил `netsh`, сброса `Internet Settings` прокси и очистки зависших сессий ядра.

## 6. Контроль утечек IP и приватность (`ip_monitor.rs`)
- Резервные копии настроек (`export_settings_backup` / `import_settings_backup`) исключают `device_hwid`, `autostart`, невалидные порты/DNS/правила и пользовательские `updateFeedUrl`/`rulepackUpdateUrl` из импорта.
- Экспорт диагностического отчёта маскирует секреты (`password`, `uuid`, `pbk`, токены, `x-hwid`, полные URL подписок и пути профиля).
- **Монитор IP** (`ip_monitor.rs`) выполняет проверку исходного и VPN IPv4/IPv6-адреса строго по явному запросу пользователя (opt-in) и маскирует отображаемый IP в UI по умолчанию (`maskIp = true`).
